# База данных Castar

Castar.Server хранит данные в SQLite и обслуживает HTTP API и Telegram-бота. Один сервер может принимать запросы нескольких WPF-клиентов. При первом запуске сервер создаёт файл `data/castar.sqlite` рядом с исполняемым файлом. Задайте `Database__SqlitePath` для размещения файла в постоянном томе или другом каталоге.

## Архивы прежней базы

### Импорт архива февраля 2022 года

Для `old_database/old_database.7z` используйте этот сценарий. На Windows с SQL Server LocalDB экспортируйте архив через Windows PowerShell 5.1.

```powershell
powershell.exe -NoProfile -File .\DataBase\Export-LegacyArchive.ps1 -ArchivePath .\old_database\old_database.7z -OutputPath "$env:TEMP\castar-legacy.json"
```

Экспорт содержит пользовательские и финансовые данные. Храните его в закрытом каталоге. Скрипт работает с копией архива во временном экземпляре LocalDB. На стороне Castar Server нужен только SQLite.

Перед импортом запустите команду без `--apply`. Она переносит данные во временную копию SQLite, проверяет целостность и выводит отчёт. Укажите выбранную в клиенте валюту через `--target`, например `RSD`. Без этого параметра в отчёте и в SQLite остаются исходные суммы в RUB, а курсы подгружаются при выборе валюты отображения.

```powershell
.\Castar.Server.exe --import-legacy "$env:TEMP\castar-legacy.json" "C:\Castar\data\castar.sqlite" --target RSD
```

Сверьте отчёт и остановите сервер перед применением. Повторите команду с `--apply`, чтобы создать резервную копию рядом с целевой SQLite и записать импорт в транзакции. Запустите сервер после завершения. Для Linux используйте `Castar.Server`, для iPhone — `/var/jb/usr/libexec/castar/castar-host` от пользователя службы с доступом к файлам. Путь к сохранённой копии выводится перед применением.

Февральский архив содержит 192 дохода, 3 482 покупки и 8 690 товаров. Владельцы сопоставляются по Telegram ID. Время хранится в UTC, а кеш курсов использует исходную московскую дату. Исходные суммы и итоги сохраняются, даже когда итог покупки отличается от суммы её товаров. Доли плательщиков и 692 строки отдельной истории расчётов остаются в архиве. Для этих данных в текущей модели учёта нет сущностей.

### Замена исторических операций более свежей копией

Разместите MDF и соответствующий LDF (например, `origin_data_base.mdf` и `origin_data_base_log.ldf`) в одном каталоге. Экспорт работает с их временными копиями и проверяет отпечатки файлов перед открытием в отдельном экземпляре LocalDB.

```powershell
powershell.exe -NoProfile -File .\DataBase\Export-LegacyArchive.ps1 -MdfPath "C:\tmp\Castar\DataBase\origin_data_base.mdf" -OutputPath "$env:TEMP\castar-legacy-fresh.json"
.\Castar.Server.exe --import-legacy "$env:TEMP\castar-legacy-fresh.json" "C:\Castar\data\castar.sqlite" --target RSD --replace-before-2026
```

Сверьте предварительный отчёт на копии базы. Пара файлов из декабря 2022 года даёт 236 доходов, 4 792 покупки и 11 981 товар.

| Источник | Последний доход (Москва) | Последняя покупка (Москва) |
| --- | --- | --- |
| `old_database.7z` | 24.01.2022 22:08:29 | 03.02.2022 20:07:00 |
| Копия MDF/LDF из декабря 2022 года | 24.11.2022 19:32:43 | 11.12.2022 22:35:00 |

Суммы хранятся в RUB, дата курса соответствует календарной дате в Москве. Категории, история расчётов (802 строки) и доли плательщиков остаются в старой базе. Предварительный отчёт указывает расхождения между итогом покупки и суммой товаров.

При применении заменяются доходы и покупки до полуночи 1 января 2026 года по Белграду вместе с товарами этих покупок. Операции с этой границы, покупки без даты, пользователи и настройки сохраняются. Для уже совпадающих данных повторный импорт показывает нулевые счётчики добавлений и удалений.

Остановите сервер и повторите последнюю команду с `--apply`. Команда сохраняет резервную копию рядом с исходной SQLite, применяет миграции схемы и заменяет исторические операции одной транзакцией. После успешной проверки SQLite запустите сервер. Для отката остановите сервер и восстановите файл из резервной копии. При восстановлении схемы с категориями используйте соответствующую версию сервера.

### Другие архивы

Для остальных схем используйте одноразовый импорт из тега `v0.3.0`. Команда и поддерживаемые схемы описаны в [инструкции того выпуска](https://github.com/krislechy/Castar/blob/v0.3.0/DataBase/README.md#перенос-из-sql-server-в-sqlite). После сверки данных укажите полученный файл в `Database__SqlitePath`.
