# База данных Castar

SQLite подходит для локального Castar. Окно приложения и Telegram-бот работают в одном процессе, а запись чека с позициями выполняется одной операцией EF Core. SQLite используется для новых установок. В настройках можно выбрать SQL Server для существующей базы или отдельного сервера.

## Перенос из SQL Server в SQLite

1. Если исходная база поставляется как архив MDF/LDF, извлеките обе части в отдельную папку и подключите копию к SQL Server LocalDB. SQL Server может обновить формат файлов при подключении.
2. В настройках базы укажите подключение к исходному SQL Server и путь к новому файлу SQLite. Выберите **Перенести данные из SQL Server в SQLite**.
3. Проверьте число перенесённых строк, выберите SQLite, сохраните настройки и перезапустите приложение.

Импорт читает четыре таблицы приложения в одной транзакции источника, сохраняет идентификаторы и связи и публикует новый SQLite-файл после успешной записи. Суммы, даты, изображения, исходные байты чеков и доступные метаданные чеков сохраняются. Повторный запуск с тем же путём защищает существующий файл от перезаписи. Для переноса схемы из архива `DataBase.zip` обновление исходной базы через SQL-скрипт не требуется.

## Работа с SQL Server

На целевой базе Castar выполните [UpgradeCastar.sql](UpgradeCastar.sql). Для пустой базы скрипт создаёт таблицы. Для схемы от 30.07.2022 и архива от 02.08.2022 он добавляет поля и индексы и отключает старый триггер пересчёта покупок. Приложение теперь сохраняет строки ручной покупки и рассчитанный итог вместе, а у фискальных чеков хранит сумму из ответа провайдера. Скрипт можно выполнить повторно. Для существующей базы используйте резервную копию.

## Что содержат архивы

| Файл | Схема и содержимое |
| --- | --- |
| `DataBase.zip` | Пара MDF/LDF от 02.08.2022. Проверено на копии в LocalDB. Импортируются 3 пользователя, 25 покупок, 117 позиций и 12 начислений. |
| `castardb30072022.sql` | Совместимая схема SQL Server с полем `RawData binary(100)`. |
| `castardb24072022.sql` | Более ранняя схема с текстовым полем `RawData`. |
| `castardb09072022.sql`, `castardb11072022.sql`, `castardb12072022.sql`, `script create database.txt` | Исторические схемы с таблицей распределения расходов `PartsUserItem`. |
| `trigger example.txt` | Исторический пример SQL-триггеров. |
| `old_database/old_database.7z`, февральский ZIP из `old_database` | Отдельные MDF/LDF-копии с одинаковыми данными в четырёх таблицах. В каждой 3 482 покупки, 8 690 позиций, 192 начисления и 692 записи истории транзакций. Используются числовые ключи и отдельные колонки распределения по плательщикам без таблицы пользователей. Для переноса этой схемы нужно определить соответствие плательщиков и правила сохранения истории и долей. |

В архиве от 02.08.2022 у 19 из 25 покупок сохранённый итог отличается от суммы позиций. Импорт переносит оба значения как записано в источнике. При редактировании ручной покупки её итог пересчитывается по позициям.
