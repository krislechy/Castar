# Castar

Castar учитывает доходы и покупки. Windows-клиент показывает данные за выбранный период и отправляет изменения по HTTP API. Castar Server хранит базу, обрабатывает сообщения Telegram и загружает позиции фискальных чеков по QR-коду.

Размещение кода и правила разработки описаны в [архитектуре Castar](docs/architecture/castar.md).

## Установка и обновление

1. Скачайте архив Castar Server для Windows x64, Linux x64 или Linux ARM64 из [последнего выпуска](https://github.com/krislechy/Castar/releases/latest) и запустите сервер по [инструкции](Castar.Server/DEPLOYMENT.md).
2. Установите [Microsoft .NET Desktop Runtime 11 для Windows x64](https://dotnet.microsoft.com/en-us/download/dotnet/11.0#runtime-desktop-11.0.0). Для первой установки клиента запустите `Castar-win-x64.exe`. Затем открывайте приложение через ярлык или `Castar.exe`.
3. В клиенте откройте **Настройки → Подключение к Castar Server**. Укажите адрес и ключ API сервера, затем нажмите **Проверить и сохранить**. Для сервера на этой же машине используется `http://127.0.0.1:5080`, для удалённого — HTTPS.

Начиная с `v0.3.0`, обновляйте клиент через **Настройки → Обновления Castar → Проверить обновления**. Castar покажет объём и процент загрузки, сверит SHA-256 ZIP по данным GitHub, заменит файлы клиента и перезапустится. Сервер обновляется отдельно заменой его архива с сохранением каталога данных и конфигурации службы.

Для однократного перехода с `v0.2.0` сначала установите Desktop Runtime и полностью закройте Castar. Скачайте и распакуйте `Castar-Update-win-x64.zip` в отдельную папку. Откройте в этой папке PowerShell и выполните команду. Если Castar установлен в другом каталоге, подставьте путь к нему первым аргументом.

```powershell
.\Castar.Updater.exe "$env:LOCALAPPDATA\Programs\Castar" (Get-Location).Path
```

Клиент хранит общие настройки в `%LOCALAPPDATA%\Castar\Castar.Client.xml`. Если этого файла ещё нет, клиент переносит параметры автозапуска и сворачивания в трей из настроек `v0.1.0` и сразу сохраняет их в новом формате. Параметры базы и Telegram задаются в конфигурации сервера.

## Установка на iPhone

Нужен iPhone ARM64 с iOS 15 или новее, rootless-jailbreak, доступ по SSH и `sudo`. Установка проверена на iPhone SE первого поколения с iOS 15.7. На iPhone нужны `bash`, `ldid`, `uicache`, `launchctl` и `tar`.

1. Скачайте Castar Server для iPhone из [GitHub Releases](https://github.com/krislechy/Castar/releases). Архив содержит сервер, наблюдатель, приложение Castar и инструкцию `DEPLOYMENT.md`. Для прямого подключения используйте сборку с поддержкой HTTPS.
2. На Windows подставьте Wi-Fi IP iPhone вместо `IPHONE_IP` и выполните команды в PowerShell. Если ваш SSH использует другой порт, укажите его вместо 22.

   ```powershell
   scp -P 22 .\Castar-Server-ios-arm64.tar mobile@IPHONE_IP:.
   ssh -p 22 mobile@IPHONE_IP
   ```

3. В сеансе SSH на iPhone распакуйте и запустите установщик.

   ```sh
   work=$(mktemp -d "$HOME/castar-install.XXXXXXXX")
   tar -xf "$HOME/Castar-Server-ios-arm64.tar" -C "$work"
   sudo /var/jb/usr/bin/bash "$work/install.sh"
   ```

   Если `ldid` находится вне PATH, передайте его путь установщику, например `sudo /var/jb/usr/bin/env LDID=/absolute/path/to/ldid /var/jb/usr/bin/bash "$work/install.sh"`.

4. Настройте [сертификат на IP iPhone](Castar.Server.iOS/DEPLOYMENT.md#сертификат-https) и добавьте его в доверенные сертификаты Windows.
5. Откройте **Ключи API** в Castar на iPhone. Скопируйте показанный HTTPS-адрес и действующий ключ или выпустите отдельный ключ. Введите их в настройках Windows-клиента.

Отдельный ZIP приложения в [GitHub Releases](https://github.com/krislechy/Castar/releases) содержит `CastarControl.app` и файл для подписи `ldid`. Для первой установки используйте полный архив, который регистрирует приложение и запускает службы.

## Хранилище

Новый сервер создаёт SQLite в `data/castar.sqlite`. Путь меняется через `Database__SqlitePath`. Для существующего SQLite из выпуска 0.1.0 остановите прежний Castar и укажите серверу путь к копии старого файла. При прежней настройке по умолчанию он находится в `%LOCALAPPDATA%\Castar\castar.sqlite`.

Castar Server использует SQLite. Если данные уже перенесены в SQLite, достаточно указать путь к этому файлу в `Database__SqlitePath`. История старых резервных копий описана в [документации БД](DataBase/README.md).

В **Настройки → Сервер → Создать резервную копию** можно скачать согласованный снимок SQLite. Для переноса архива MDF/LDF и пробной сверки используйте [инструкцию импорта](DataBase/README.md).

## Отображаемая валюта

В **Настройки → Приложение → Отображаемая валюта** выберите валюту для сумм и итогов. Под пересчитанной суммой видны исходная сумма и код валюты. В режиме **Исходная валюта** итоги разделены по валютам. Сервер хранит исходные суммы, коды валют и кеш исторических курсов в SQLite. При отсутствии курса за дату операции сервер может использовать ближайшую предыдущую котировку в пределах семи дней. Суммы без исходной валюты или доступного курса видны в списке и исключаются из соответствующего итога. [Дневные исторические курсы Frankfurter](https://frankfurter.dev/)

В разделе **Статистика** выберите период для графиков и итогов. В карточке **По категориям** можно переключать расходы и доходы и выбирать категории галочками. Выбор сохраняется отдельно для расходов и доходов. Если отображение идёт в исходных валютах, валюту графиков можно сменить в самом разделе.

В **Настройки → Приложение → Уведомления** выберите уведомления Windows или Castar. Для Castar можно указать угол экрана и число одновременно видимых уведомлений. Щелчок по уведомлению открывает операцию.

## Telegram и чеки

Укажите `Castar__Telegram__Token` и `Castar__Telegram__Enabled=true` в окружении сервера и перезапустите его. Отправьте `/me` в личном чате, чтобы узнать Telegram ID, затем добавьте пользователя с этим ID в клиенте. Чтобы выключить автоматические уведомления бота для пользователя, откройте его двойным щелчком в **Настройки → Пользователи**, снимите флажок **Отправлять уведомления** и сохраните.

Выберите поставщика чеков в **Настройки → Сервер**. Налоговая Сербии использует анонимную авторизацию. Для ФНС России нажмите **Установить данные для входа**, укажите ИНН и пароль и сохраните настройки сервера. Для первичного запуска поставщика также можно задать через `Castar__Receipts__Provider`. По умолчанию используется `serbia`. [Сервис проверки чеков TaxCore](https://tap.suf.purs.gov.rs/Help/view/1665995733/Invoice-Verification-Service/en-US)

В **Настройки → Сервер** можно выбрать разрешённые валюты и валюту ручного добавления. В Telegram пишите каждый товар с новой строки и указывайте его валюту после суммы, например `Хлеб 150 RSD` и `Книга 300 RUB`. При добавлении новой строки без кода действует валюта ручного добавления, при редактировании сохраняется текущая валюта строки. Для дохода действует тот же формат суммы и валюты, например `/income Оплата 100 EUR`. При ошибке бот возвращает разрешённые коды.

В **Настройки → Сервер → Настройки Telegram** можно выбрать значки операций. Зарегистрированный пользователь может выбрать **Добавить покупку** в меню бота или отправить `/purchase` в личном чате либо в группе с ботом. Ответьте на запросы названия и суммы, выберите валюту и нажмите **Сохранить**. Отмена доступна кнопкой или командой `/cancel`. Команда `/info` показывает форматы ввода и способы изменения и удаления операций. Покупки, созданные через `/purchase`, редактируются и удаляются в Castar.

Чтобы убрать покупку, созданную обычным текстовым сообщением, отредактируйте это сообщение. Сохраните число строк и укажите отрицательную сумму в одной из них. Для сообщения с начислениями отрицательная сумма удаляет начисление из соответствующей строки. Удаление самого сообщения в обычном чате Telegram не передаётся боту. [Telegram Bot API — Update](https://core.telegram.org/bots/api#update)

Если QR мелкий или бледный, отправьте исходное изображение как файл до 20 МБ. Так Telegram передаст его в исходном качестве. Можно также вставить ссылку из QR-кода.

При временной недоступности поставщика Castar сохраняет запрос в SQLite и автоматически повторяет его у того же поставщика, в том числе после перезапуска. Интервал по умолчанию — 5 минут. Его можно изменить в **Настройки → Сервер → Повтор чека, мин**. Если поставщик указал более длительный срок ожидания, Castar учтёт его. Бот обновляет сообщение о результате.

## Категории и локальная модель

Создавайте и редактируйте категории и иконки через **Настройки категорий** в доходах и расходах. Доходы сгруппированы по категориям. При создании покупки категорию можно выбрать для каждого товара. Castar запоминает подтверждения для следующих покупок того же товара в том же магазине и для доходов с тем же источником.

Сервер однократно добавляет 20 базовых категорий расходов и 9 категорий доходов со значками и тегами. Если категория с тем же названием уже есть в соответствующем списке, сохраняются её настройки. Базовые категории можно редактировать и удалять.

В редакторе категории можно добавить теги, например «молоко» или «йогурт» для категории «Молочные продукты». Enter добавляет тег, крестик удаляет его. Модель использует теги как подсказки при выборе категории.

В **Настройки → Автоматическая категоризация** выберите Ollama или llama.cpp, найдите установленную модель и нажмите **Применить**. Категоризация выключена по умолчанию. Рекомендуемая модель Ollama — `qwen3:4b-instruct-2507-q4_K_M`, примерно 2,5 ГБ на диске. Для llama.cpp можно использовать GGUF Q4_K_M той же модели. Потребление памяти зависит от контекста и параметров запуска. [Ollama](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M) · [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)

- **Внешний сервер.** Укажите адрес работающего HTTP API. Для Ollama Castar передаёт время выгрузки в каждом запросе. Во внешнем llama.cpp время сна можно задать на самом сервере. Для совместимого роутера Castar также умеет выгружать модель, которую сам загрузил.
- **Управляется Castar.** Установите исполняемый файл Ollama или `llama-server` и модель. Для llama.cpp укажите каталог с файлами GGUF. Castar запускает локальный процесс по первому запросу или кнопке **Запустить** и завершает его после выбранного простоя или по кнопке **Остановить**.

Кнопка рядом с **Настройки категорий** показывает количество доходов или покупок с товарами без категории и запускает обработку за выбранный период. Очистка категории возвращает запись в очередь. Кнопка рядом с **Добавить товар** пересчитывает категории всех товаров выбранной покупки, включая ручные назначения. Кнопка **Обработать историю** в настройках ставит в очередь старые товары без категории за всё время. Категоризация использует встроенный промпт и теги категорий.

Для работы с удалённым Castar Server через браузер примените эти настройки в клиенте Windows, завершите Castar и запустите на компьютере с моделью `Castar.exe --categorization-agent`. Нажатие на значок в области уведомлений останавливает агент. Сервер Castar хранит категории, очереди и подтверждения. Модель получает от клиента названия товаров и магазин либо источники доходов, а также соответствующий список категорий. Если модель недоступна, операция сохраняется и остаётся доступной для ручной классификации.

## Сборка

Установите [.NET SDK 11](https://dotnet.microsoft.com/en-us/download/dotnet/11.0) и выполните на Windows `dotnet build Castar.sln -c Release`. Тег `vX.Y.Z` должен совпадать с `Version` Windows-клиента.

- Для выпуска с изменениями сервера установите эту же версию в сервере и iPhone, увеличьте номер сборки iPhone и обновите инструкции в пакетах. CI соберёт клиент и серверы Windows/Linux и создаст черновик. Соберите TAR сервера и ZIP приложения iPhone из того же тега. В рабочей копии этого тега с Python 3.11+ и авторизованным GitHub CLI выполните `python .github/scripts/castar_release.py publish-full vX.Y.Z <каталог-пакетов-iPhone>`. Команда добавит пакеты iPhone и SHA‑256 и опубликует выпуск. Первый выпуск с этой схемой создаёт исходный набор серверных пакетов с метками версий.
- Для клиентского выпуска сохраняйте прежние версии сервера и iPhone. CI проверит изменения относительно исходного серверного тега, добавит пять прежних пакетов Windows, Linux и iPhone, затем опубликует выпуск. Метка каждого серверного файла сохраняет его фактическую версию. Новый сервер устанавливается вручную только при изменении версии пакета.

Публикация проверяет состав и SHA‑256 пакетов по метаданным GitHub. Полные прогоны установщика и обновления выполняются отдельно при изменениях в них. Комплекты доступны в [GitHub Releases](https://github.com/krislechy/Castar/releases).
